## Characterized behavior and unresolved specification work

Current behavior: the resident and visualization use the checked [`Canonical.step` adapter](../src/canonical/adapter.ts); the resident retains native token, payload, and effect handles while canonical Bend owns policy transitions. [`Lifecycle.apply`](../packages/agent-flow-bend/Lifecycle.bend) remains a separate tested model with no production consumer. The [authority map](bend-logic-authority-map.md) and [export inventory](bend-generated-export-inventory.md) are historical #117 audit checkpoints, not current import maps. Capacity replacement remains ordered partial admission. The installed profile remains same-file/32 KiB, with #132's file settings replacing the grant. These facts characterize code; they do not alter the accepted cross-file target.

Specification gaps: #141 must settle supported import forms, resolution scope, deterministic traversal and finite cumulative file/read/work limits. #93 adoption must freeze canonical evidence encoding, renderer and initial complete-request bound before egress. #120/#122 must choose exact ledger limits using bounded materialization and near-limit fixtures. #140 later refines provider-aware full-request sizing; #139 later considers bounded capacity retry. Uncertain host output is **not** permission to assume delivery: canonical transitions need explicit write-start, acknowledgement, failed/unknown, and stale callback outcomes under R4.
