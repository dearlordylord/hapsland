## Declared live allocation

At most **two sequential authenticated Claude sessions**, each with one host invocation, are permitted: `control`, then `finding` only if the control passes. At most **three Hapsland application-level provider dispatch reservations** total: one control, one initial finding, one repair review. No reset, replacement arm, automatic retry, or post-result sample extension. The live trial's total wall-clock allocation is 180 seconds; each host session has a 90-second ceiling and 2 MB combined stdout/stderr ceiling. Retain the 4.4-second bridge and five-second native hook caps. Use exact Claude `2.1.218`, Linux/aarch64, `-p --output-format stream-json --verbose --no-session-persistence`, `--allowedTools Read,Edit,Write`, and `--permission-mode acceptEdits`, with the normal authenticated Claude provider/model. OpenCode and shell-written files are outside this allocation.

The control asks Claude to write the one-line branded type `type OrderCount = number & { readonly __brand: "OrderCount" }`. The finding arm asks for the one-line bare type `type OrderCount = number` and a native `Edit|Write` to the branded line only if Hapsland returns a finding. These distinct synthetic sources make a real clear/finding pair possible without substituting backend answers. Count each exact initial `Write`, matching successful `PostToolUse`, repair, final file, and source-free review outcome. The live Jev answer is probabilistic: do not manufacture a finding or adjust thresholds after seeing the control. Freeze the Noul pack, threshold, and fixtures before allocation, and record an unexpected clear/finding as a genuine outcome.

| Arm | Required observation for pass |

| Control | One exact branded initial native `Write` and matching successful hook; one attributable live Jev `clear` activity stage within that hook; no host finding, notice, or repair; exact branded final file; normal host exit. If Jev returns a finding here, mark the control failed and stop. |

For each arm, record host launch to native edit, native edit to hook return, live review terminal stage, handoff classification, later native repair, and host close. The interval from a streamed native event to bridge return includes host stream observation delay; do not label it pure Jev or model-read latency. `PostToolUse` occurs after the edit, so a block does not roll it back. A block without a later native repair is delivered but fails the reaction gate. A live clear in the repair hook is required; a repaired file alone cannot establish it.

## Preflight and stop rules

Before claiming either ledger start: check clean intended code and fresh build; exact executable version; same executable's `auth status --json` reporting `loggedIn: true` without retaining its output; isolated user opt-in, configuration and consent; destination identity; credential availability through Hapsland's nonprinting status/doctor path; and fresh budget/ledger. Do not start until the normal hook process can resolve that credential. The `.env` presence check above is not sufficient.

Stop and mark the consumed arm failed or incomplete on any failed gate, missing credential/consent, wrong version, abnormal login, live backend error/timeout, stale attribution, late terminal result, hook or host timeout, output cap, forced close, extra edit/call reservation, or ambiguous handoff. Do not rerun a consumed start or reuse its ledger. Delete temporary source and raw streams after producing the allowlisted summary, including on interruption. Report partial evidence as partial; a failed control prevents the finding arm. A pass supports only this exact profile, fixture, destination, user opt-in, and two selected sessions; it does not establish broader Claude compatibility, stable Jev classification, or a repair rate.
