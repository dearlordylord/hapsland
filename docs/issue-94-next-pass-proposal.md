# Issue #94: proposed next host acceptance pass

**Decision requested:** defer authenticated Stage A while the offline control timing gap below is resolved, then review the bounded follow-up. This is a proposal for review, not authorization to start sessions. Neither Claude Code nor OpenCode is declared supported.

## Evidence behind the proposal

The first [Claude Code 2.1.218 pass](issue-94-host-validation.md) used five authenticated headless sessions with an offline controlled Hapsland backend. The no-advice control passed. The finding fixture made one matched native edit and produced one context submission, but no later native repair; the retained evidence cannot classify that older submission as a rule finding rather than an operational notice. The stale fixture changed the file before review admission could be established. The timeout fixture kept the edit and returned without advice in 4.361 seconds. The unavailable-backend fixture kept the edit but produced one unclassified context submission. The five-session ceiling is exhausted. Restart and a true host failure were not exercised. OpenCode 1.14.44 has no saved provider credential and had no authenticated run. These are selected outcomes, not delivery rates.

The [#97 Codex measurements](issue-97-delivery.md) show why host submission, model reaction, and latency need separate evidence: a subsequent-hook path stranded a finding without a later edit; a bounded Stop collector produced same-turn repairs when results were ready, while late results timed out; native background output sometimes reached the model and sometimes lost its opportunity at headless teardown. Those results concern Codex 0.156.1 and do not establish Claude or OpenCode behavior. The five-second Stop bound was only a candidate, not a validated cross-host promise. For #94, measure each host's own hook launch, review completion, submission, later native edit, and session end rather than importing Codex timing assumptions.

## Offline preparation and remaining readiness gap

1. **Handoff and reaction classification:** [the classifier](../evidence/host-94/validation/handoff-classification.mjs) recognizes the exact synthetic rule marker or approved operational-notice text in each host's output shape. The [reducer](../evidence/host-94/validation/reaction-events.mjs) requires a classified finding, matching first native call, later distinct model-issued repair call, and completed repair hook. Unknown event shapes remain unproven. The runner separately counts any nonempty host handoff that the classifier does not recognize, so the control, stale, and timeout cases cannot pass on an unknown message. A shared initiating-call predicate requires exactly one matched model-originated native edit and successful hook finish with finite timestamps; control also requires a matching controlled review completion. Timeout and unavailable-backend cells require that initiating call and an observed admission marker. A shell-authored file, unloaded hook, mismatched call, or missing timestamp is incomplete. It records finding opportunity as `undelivered`, `submitted-unreacted`, or `observed-reaction`. The [offline scripted bridge tests](../evidence/host-94/validation/host-session-integration.test.mjs) cover both host shapes, unknown event and handoff controls, and unavailable-backend notices. They execute the generated bridge and production controlled CLI with a fake host/provider, not the authenticated host binary.
2. **Ordered stale race:** The runner waits for the resident's source-free accepted-admission marker while a controlled backend gate holds evaluation. Before mutation it also requires one in-flight bridge start whose hashed key/tool match one initial native edit; a mismatched call remains inconclusive in both scripted host fixtures. It then removes the eligible synthetic alias and releases the gate. Both matched scripted fixtures and the [resident race test](../evidence/host-94/validation/race-restart.test.mjs) passed with no stale finding delivered. **Real-host exact admission attribution remains unproved:** the production marker contains only `accepted`, without a call alias. Other merged hooks could exist outside this trace. The runner blocks real-host stale and admission-triggered host-failure before claiming a ledger slot or launching a host; its defensive acceptance check also cannot pass those cells without exact attribution.
3. **Restart and host failure:** The runner prepares `restart-old` and `restart-new` as two ledger-counted host sessions with a shared temporary fixture, stopped old resident, different hashed recipient, and new-only backend outcomes. Both scripted host-shape restart pairs passed. The resident fixture independently showed queued old work did not dispatch after restart. This covers work **queued before backend dispatch**, not an in-flight provider response. Scripted host termination after admission also preserved the completed synthetic edit for both shapes, but the generic marker prevents a real-host exact admission claim; real-host failure behavior remains unmeasured.
4. **Cumulative gate:** The [pass ledger](../evidence/host-94/validation/pass-ledger.mjs) must be initialized in a new explicit directory and passed as `HAPSLAND_94_PASS_LEDGER` before any pass. It atomically records starts, allows one unfinished host session globally, enforces eight starts per host and sixteen total, and never refunds failed or abandoned starts. The runner permits a finding case only after a passing control, and Stage B only after both Stage A cases pass; failed or incomplete cases stop that host's subsequent invocations. It pins Claude to cached `2.1.218` and OpenCode to exact `1.14.44`, then performs a read-only auth check with that selected executable before claiming a slot. A missing or corrupt ledger or unauthenticated profile fails closed. The temporary restart fixture is a sibling of the ledger and is removed after `restart-new` or an incomplete `restart-old`; if the operator stops between a passing old and new session, inspect and finish or explicitly clean that synthetic fixture before abandoning the pass.

The runner now enforces the 2 MB ceiling on **combined stdout and stderr**; a fixture with 1.1 MB on each stream stopped as incomplete. Focused offline tests for shell-authored files, unloaded hooks, mismatched calls, missing timestamps, and zero-hook timeout/unavailable cells passed. The scripted provider reactions are **not** acceptance evidence of a normal model. No authenticated host or Jev call occurred during this preparation, and the five older Claude records were not changed.

It did not pass the one-successful-hook gate. This single result does not locate the remaining time within cold resident startup, review work, and collection; it does rule out source TypeScript startup as a sufficient fixture-only remedy here. **Proposed product-owned test seam for exact admission:** When a fixture supplies an ephemeral HMAC key through a dedicated test-only environment variable, the resident should write a versioned, source-free admission marker containing an HMAC-SHA256 alias for the accepted recipient. Define the canonical HMAC input as an ordered, length-delimited tuple of host, session ID, turn ID (or null), tool-use ID, and agent ID (or null). The bridge independently computes the alias from the native initiating call and requires exactly one match before mutating the stale file or triggering host failure. A missing, duplicate, or mismatched alias leaves the case inconclusive without mutation or termination. Keep the current `accepted\n` marker when the test variable is absent, and delete the temporary key and marker with the fixture. Neither raw identifiers nor the HMAC key belong in retained evidence. This change needs a separate product owner review and deterministic tests; it is not implemented by this proposal.

## Proposed bounded run, only after offline checks pass

Use one disposable Git repository and isolated Hapsland state per scenario, except the two restart sessions intentionally share a temporary synthetic repository and consent state. Use a normal authenticated host provider/model and a controlled offline Hapsland backend. Run sequentially, away from #95 paired runs. Each session gets one synthetic initial native edit request, a 90-second host ceiling, and a 2 MB output ceiling. Claude Code has a five-second host-enforced native hook timeout. The OpenCode 1.14.44 adapter uses a 4.5-second plugin watchdog and bounded return path; this is an adapter bound, not a native OpenCode hook timeout. No Jev calls. Stop the entire host pass on a version/auth mismatch, raw-data retention, unbounded process, output ceiling, or edit failure. The staged cap is **eight sessions per host, sixteen total**; the ledger enforces it across invocations. The owner must initialize the new ledger once before launch and retain its source-free entries; never reset it to regain slots.

| Stage | Sessions per host | Proceed condition |
| --- | ---: | --- |
| A: all-clear control and rule finding | 2 | Control has one native edit, zero submissions and no repair. Finding has a classified rule submission, matched native initial call, later matched model-originated repair after submission, and final repaired file. If either fails, stop that host; report submission and reaction separately. |
| B: stale, no-later-event/timeout, backend unavailable, host failure, and restart pair | Up to 6 | **Do not start stale or admission-triggered host-failure acceptance until exact call admission can be proved.** After that gate and Stage A pass, stale requires post-admission mutation and zero host handoffs; timeout and unavailable remain bounded and preserve the edit, with notices and unclassified messages counted separately. Host failure preserves the completed edit and reports whether the host or hook failed. Restart uses two sessions and proves no old recipient advice reaches the new one. A no-later-event result is recorded in one of the three explicit categories. |

For each run, record host version, mode, platform, scenario, host outcome, initial native call matched, review admission marker observed, matching controlled review completion outcome (or `not-observed`), classified finding/notice submission count, observed native-event-to-hook-finish interval for the initial submission (or null), later matched repair, final synthetic state, and any ceiling hit. The runner timestamps host stdout receipt and bridge hook finish relative to process launch; that interval includes host output buffering and scheduling uncertainty and is **not** native edit-to-agent-visible latency. The current admission marker is global and unkeyed, so admission is recorded as `unattributed-global-marker`, never as exact recipient proof. A host-event timestamp after advice is a repair opportunity observation, not proof of when the model read the finding. Do not retain raw JSONL, prompts, source, credentials, model replies, or source-bearing Jev responses.

OpenCode may enter Stage A only after a read-only check reports a usable credential for the **same profile** used by `opencode run`, and its exact 1.14.44 binary and plugin-loading mode are verified. Current `opencode auth list` reports zero credentials. A missing login is a prerequisite failure, not an adapter failure; do not launch an OpenCode model session to discover it.
