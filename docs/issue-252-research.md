## Where information is lost today

1. [capture.ts](../packages/native-observation/src/direct-event/capture.ts) performs descriptor-anchored, bounded, matching reads, then returns `undefined` for all caught failures. Its error carries no category. Size and nonregular-file checks share one error; decoding, changing metadata, disappearance and identity/access checks also collapse. Current maximum is 2,097,152 bytes, with a configured lower effective cap possible.
2. [pipeline.ts](../packages/review-execution/src/direct-event/pipeline.ts), `captureCandidateRoot` and `prepareCandidate`, assign `capture-unavailable` to unavailable root capture **and** a false `beforeAnalyze` admission result. Root capture also refuses aggregate file/read budgets before opening a source, so an undefined result cannot safely be labeled a read failure.
3. [preparation-workspace.ts](../packages/resident-runtime/src/resident/preparation-workspace.ts) already accepts measured source bytes and measured preflight. Unknown preflight still reserves `MAX_TYPE_DECLARATIONS * MAX_SOURCE_BYTES`; expanding that fallback or resident capacity is a separate bounded-resource decision, not necessary to make refusal visible.
4. [server.ts](../packages/resident-runtime/src/resident/server.ts) already owns actual workspace admission/resize and records preparation omissions from path outcomes. Both normal and controlled-writer preparation paths need consistent observations; initial workspace refusal can occur before the pipeline runs.
5. [model.ts](../packages/review-definition/src/direct-event/model.ts) and [inspection/contract.ts](../packages/inspection-records/src/inspection/contract.ts) currently carry an omission reason without capture limit metadata. The existing journal/replay infrastructure transports inspection records; [replay.ts](../packages/inspection-records/src/inspection/replay.ts) already describes loss and cursor gaps.
6. [page.ts](../packages/administration/src/inspection/page.ts) has existing omission labels, omission rows and details. Extending those is sufficient; a new dashboard or replay engine is unnecessary.

## Minimal recommended repair

Carry one small, source-free refusal description from the boundary that knows it, through the existing path outcome and `preparation-omission` fact. Use a bounded reason and numeric effective limit for size refusal; optional observed size should be reported only when trustworthy descriptor metadata exists. Do not emit raw exception messages, source text, credentials, or native stderr. Path disclosure follows #256 inspection consent rather than a blanket path ban.

The initial proposal grouped capture size refusal, other unavailable capture, and preparation admission/resource refusal. The owner subsequently chose finer observed failure distinctions as recorded above. A stable-read failure does not need a separate product category for every OS errno. Keep genuinely missing evidence unknown. Preserve the generic old reason only as an honest rendering of evidence already lacking detail, not as a second production pathway or format version.

Replace the overloaded materialization-refusal reason directly. The boolean admission port identifies the boundary but does not prove a resource cause; preserve observed refusal categories from its authority where an elegant typed result change is possible. A new resource service is unnecessary. At the resident owner, expose initial reservation refusal as well as resize refusal. At the pipeline owner, distinguish aggregate capture budget refusal from filesystem capture refusal.

For source capture, prefer enriching the existing Effect failure/result boundary over inventing a diagnostics bus or a second capture implementation. A small existing-hook extension could reduce adapter churn, but it must carry refusal into the preparation result; a best-effort inspection callback alone cannot make authoritative outcomes or dropped evidence reliable. Choose one path after checking all `captureStable` consumers, and remove superseded error plumbing in place.

The Darwin helper needs attention: [capture-open.c](../native/src/capture-open.c) currently combines `fstat`, nonregular and oversized refusal in exit 72, and the TypeScript bridge discards failed subprocess details. Split only the needed source-free native failure codes/metadata at the existing helper boundary; a separate pathname `stat` after failure would weaken causality and race against the refused descriptor. This is a packaging/native-consumer concern, not only a label change.

Reuse journal storage and replay. #256 owns updates to the version-one persisted fact schema and omission renderings; #252 supplies the typed producer facts and resident mapping through the accepted handoff. The browser should explain, for example, “Source exceeds capture limit (limit: … bytes)” versus “Source capture unavailable” versus “Preparation refused by resource admission.” Keep accepted ingress and evaluated badges separate.
