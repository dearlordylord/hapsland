# Connector feasibility for Hapsland's security gate

**Date:** 2026-09-24. **Status:** Advisory investigation. This note proposes a verification contract; the product specification must adopt or revise it. No Hapsland model or Hapsland connector driver has been run. The local connector and its isolated RC.116 worktree were inspected and exercised.

## Decision and scope

Classify `@firfi/quint-connect` as **OPTIONAL INTEGRATION** for a bounded first prototype and its Effect driver pattern as **BORROW**. Hapsland owns the connector, so RC compatibility is maintainable. The first driver must call Hapsland's production direct-event path: `prepareObservation` followed by `evaluatePrepared`, with a second resident-process witness for queued dispatch. The legacy `ReviewBackend`, `SnapshotReader`, and `ReceiptStore` ports do not cover that path and are insufficient evidence for this gate.

## Exact driver contract for the first prototype

Use `@firfi/quint-connect/effect`: `defineDriver(actionPickSchemas, factory)`, `quintRun({ spec, driverFactory, stateCheck, seed, nTraces, maxSteps, quintBin })`, and `stateCheck(decodeSpecState, compareState)`. The factory creates **fresh fixture state per trace**. Each action handler executes one production operation against a temporary Git worktree and current config/consent fixture; `getState` returns the observed state after that action. Provide test `DecisionModel` and consent layers with `Effect.provide` around `quintRun`. Pick schemas must be service-free Effect codecs.

For the direct-event path, start with actions that change exclusions and consent, observe an edit, prepare it, and attempt dispatch. `prepareObservation` has `captureHooks.sourceRead` for an observable read ledger. `controlledDecisionModelLayer({ inspectRequest })` exposes the complete `ProviderOptions` input and decision definitions **before** provider serialization. Record only synthetic fixture labels/digests and classifications, never source text in CI artifacts. `evaluatePrepared(prepared, beforeDispatch)` uses the real production payload builder (`preparedProviderInput`) and production `DecisionModel` call. The driver state should contain the current policy generation, prepared item identity, read ledger, DecisionModel call count, authorized payload fragment IDs, actual payload fragment IDs, and terminal status. Compare those with the Quint state after each action.

For the queued-work property, a second witness must use `makeResidentDispatchContext` → `admitObservation` → resident preparation/queue → `collectReady`. Its observation seam must be serializable across IPC: a local loopback HTTP receiver behind the installed `@effect/ai-typesafe` client can capture the **serialized** request and endpoint, or a narrowly scoped test-only resident ledger can report the same facts. The existing `inspectRequest` callback cannot cross resident IPC because `makeResidentDispatchContext` deliberately omits it. A direct-function driver alone cannot establish reauthorization after queuing.

The connector's `stateCheck` only compares what `getState` reports, so the fixture must observe real sinks. The first gate should explicitly require: a fixed seed printed on failure; a pinned `quintBin`; a positive minimum trace and action count; coverage of each named action; rejection of any unmapped `step` or anonymous non-init action; `stateCheck` and `getState`; and a deliberate source-egress mutation that fails. `NoTracesError` handles zero traces, but a trace with only skipped step 0 can still pass. `nTraces: 200` and `maxSteps: 20` are reasonable initial bounded exploration settings; the actual generated count must be checked against the requested count and CI duration measured. Keep synthetic source fixtures only.

## Remaining integration work

1. Build a finite Quint model and a typed Hapsland driver in an isolated Hapsland branch. Include named actions for exclusion change, consent change, observation, preparation, queueing, dispatch, and failure. Avoid the literal action name `step`, or make connector dispatch strict before using it as a gate.
2. Add the resident witness and serialized HTTP capture. Compare complete request bytes or a lossless parsed request with an independent payload authorization oracle. DecisionModel inspection alone cannot establish what the provider receives.
3. Inject one forbidden dispatch and one source-bearing disk write; both must fail the gate. A green model or driver without sink mutation sensitivity is advisory only.
4. Re-run the RC.116 connector checks from the worktree against a real Hapsland consumer package before adopting the dependency; pin the connector and Quint CLI versions. The current packed smoke is connector-local, not a Hapsland consumer run.
