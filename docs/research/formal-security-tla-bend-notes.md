# TLA+ and Bend for Hapsland security: targeted research notes

**Date:** 2026-09-24. **Status:** advisory evidence for [the formal-security research pass](PRODUCT-RESEARCH-ADVISORY-2026-09-24-FORMAL-SECURITY.md), not a product requirement. **Scope:** TypeScript code connection for Hapsland's source egress, local persistence, and folder-access decisions. This is a targeted named-candidate pass under the [product research methodology](../../../hapsland-research/PRODUCT-RESEARCH-METHODOLOGY.md); it does not claim an exhaustive tool survey. Sources were accessed 2026-09-24. No formal tool or TypeScript conformance harness was run in this pass.

## Research question and decision boundary

Can TLA+/PlusCal/TLC, Apalache, or Bend 2 establish a CI gate that catches a change in Hapsland's TypeScript implementation which would send excluded source to Jev or persist source outside approved locations? The existing-solution baseline is a model checker plus a code-level observation or conformance harness; a detached passing model cannot answer the code question. Evidence that would change the assessment is a maintained TypeScript-to-tool refinement bridge for the exact relevant IO effects, or a demonstrated small Bend implementation that owns the production policy boundary.

The workflows to cover in a later prototype are: advisory review after an edit, optional blocking, two installed agent-host adapters, headless execution, and Jev timeout/failure. Model-provider behavior matters only where it changes egress. The first security property should be expressed at actual boundaries: read/source selection, payload construction, Jev request, log/cache/write, and host handoff. Include configuration precedence and symlink/canonical-path cases before claiming folder exclusion is enforced.

## Code-connected gate shape to prototype

1. Define a small abstract vocabulary: `Select(path, origin)`, `Allow/Reject`, `Read`, `BuildPayload`, `Send(destination, fields)`, `Persist(path, fields)`, `ReviewFailed`. Label source text, path, metadata, findings, and credentials separately; “no source leaves” is false if Jev must receive selected source. The candidate invariant is that only source from an allowed, canonical path and consented repository may reach the declared Jev destination, and no source-bearing data reaches undeclared persistence or diagnostic channels.
2. Model configuration precedence explicitly: user exclusions, host-provided paths, repository consent, default scope, canonicalization, symbolic links, deleted or renamed files, and runtime configuration changes. State what happens when path resolution or config loading fails. Avoid treating a configuration declaration as evidence of enforcement.
3. Instrument the TS functions that make **actual** send/write decisions, using an injected transport/filesystem seam in offline checks. Project source to labels and hashes so retained traces contain no source. Capture the exact action order plus negative cases: excluded directory, symlink traversal, consent absent, simultaneous hosts, Jev timeout, retry, and logging/error paths. The projection must include every egress/persistence sink or the conformance claim is incomplete.
4. Gate CI on both bounded model checking and implementation conformance tests. Use model traces as generated scenario inputs and check TS event traces against the model; include mutation probes that deliberately bypass exclusion or add a write to prove the gate catches drift. Record the model bounds, instrumentation coverage, and exact fail condition. Treat passing sampled traces as evidence for those scenarios only [T6,T7].

The strongest case against this path is that a second abstract model can stay green while an unobserved TS sink leaks source. The decision should change if the spike cannot enumerate all real sinks and put them behind a testable seam, or if observed trace validation has to discard path/consent facts required to detect the bug. For Bend, a generated-JS policy core would be worth reconsidering if a prototype demonstrates artifact pinning, proof failure on a policy mutation, and safe wrapper behavior across actual host entry points.
