# Quint and TypeScript trace connection: targeted advisory notes

**Date:** 2026-09-24. **Scope:** named-candidate architecture pass on Quint and `@firfi/quint-connect` for Hapsland's source-egress, disk-write, and folder-access policies. This does not establish ecosystem coverage or adopt a dependency. It supplements the formal-security advisory; product specification must decide which proposals become requirements. Sources were read 2026-09-24. No local Quint run or Hapsland connection prototype was executed.

## Research brief and decision

The question is whether a Quint model can stay connected to Hapsland TypeScript tightly enough for a useful security quality gate. The existing-solution baseline is Quint model checking plus model-based tests against Hapsland's actual public decision functions and effect ports. The target workflows are post-edit feedback, optional blocking, concurrent installed host integrations, headless use, and Jev failure. A disconfirming result would be a released connector compatible with Effect RC.116 and an end-to-end Hapsland driver that exercises all real source-to-network and source-to-disk paths with a trustworthy observation seam. Discovery was limited to official Quint docs, Quint Connect sources, the TypeScript port source, and its npm metadata; this is a targeted pass.

| Component and use | Classification | Reason |
| --- | --- | --- |
| Quint CLI for a small security state model and bounded checking | **OPTIONAL INTEGRATION** | Useful design and CI check, but model checking establishes model properties only [Q1, Q2]. Pin the CLI if selected. |
| `@firfi/quint-connect` as a Hapsland test dependency | **OPTIONAL INTEGRATION** | It can replay model traces against real TypeScript [Q3, Q4]. Current published Effect 4 variant targets RC.112 while Hapsland pins RC.116 [Q7]; gate remains unresolved. |
| Connector's trace-driver pattern | **BORROW** | A local driver against Hapsland's production ports can make the intended path observable without coupling production to the package [Q3, Q4]. |

## Code connection and security boundary

Use two distinct gates. First, `quint typecheck` and `quint verify` check a deliberately finite model for properties such as “an excluded path never reaches the network sink,” “a source-bearing payload reaches only an approved endpoint after consent,” and “no source-bearing value is persisted outside the approved receipt form.” This is a model claim [Q1, Q2]. Second, generate named traces and replay each action through a test driver calling Hapsland's actual configuration resolution, eligibility, review request construction, and storage services; inject recording network and filesystem ports and compare the observed output or state after every transition [Q3, Q4]. This is a sampled implementation conformance claim, not a proof of all code paths [Q2].

For an initial driver, model `Configure`, `ObserveEdit`, `ReadSnapshot`, `RequestReview`, `WriteReceipt`, `FailBackend`, and `Restart` actions. Represent path class (allowed, excluded, outside root, symlink/alias), consent state, payload class (source, metadata, secret), remote outcome, and disk record class. Compare the *actual* destination, payload classification, and store calls at ports after each action. Keep fixtures synthetic and avoid recording source content in CI artifacts. Test all supported host ingress adapters through the same decision service, with adapter-specific witness tests for bypass routes. A failure or timeout of Jev belongs in the model because it changes the egress and disk trace.

The strongest gate this yields is: properties hold for the abstraction and every generated trace executed by the driver conforms to that abstraction. It does **not** establish noninterference for arbitrary TypeScript, prevent an unmodeled `fetch` or `fs.writeFile`, or prove a real agent host prevents an action. To reduce this gap, route all source-bearing network and persistence operations through narrow effect ports, ban or review direct sink calls outside those ports, cover every production adapter and CLI path with sink witnesses, and review model/driver changes together. A CI job can require pinned `quint verify` and replay tests; branch protection can require the job, but local bypass, a weak abstraction, mocked internals, or newly added direct I/O can still evade it. These are proposed product controls, not established guarantees.

## Dependency gates and next experiment

| Mandatory gate for depending on the connector | Status | Resolving experiment |
| --- | --- | --- |
| License | PASS | Apache-2.0 declared in published/source manifest [Q8]; legal policy still decides acceptance. |
| API and RC.116 compatibility | UNRESOLVED | Install the packed Effect 4 variant into an isolated RC.116 consumer with package-manager strict peers, typecheck, then replay one state-checking trace. No production dependency until this passes [Q7]. |
| Real Hapsland path conformance | UNRESOLVED | Build one driver against production decision/port services and deliberately inject a forbidden egress and forbidden disk write; gate must fail [Q4]. |
| Trust/egress and supply chain | UNRESOLVED | Pin connector and Quint CLI integrity/version, disable implicit `npx` fallback with `quintBin`, inspect transitive package and CI network behavior [Q5, Q7]. |
| Failure and no-trace behavior | UNRESOLVED | Exercise missing Quint, malformed trace, no trace, handler error, state mismatch, subprocess termination, and Jev failure; require nonzero gate outcome [Q6]. |
| Maintenance and exit cost | UNRESOLVED | Confirm RC.116 support ownership or carry a small local trace runner using ITF; assess update cadence against Quint CLI changes [Q8, Q9]. |

**Handoff:** Take the finite security model and port-observation contract to both specification and prototype. First decide the allowed source/metadata egress and receipt persistence policy, then make the test driver call the exact production functions. The existing connector is sufficient as a trace-replay candidate, but its current published Effect cohort does not yet satisfy Hapsland's dependency baseline. A successful RC.116 packed consumer and deliberate-leak mutation would change that recommendation. This pass stops at the named candidate; it did not search other TypeScript connectors or run Quint, so runtime and coverage claims remain open.
