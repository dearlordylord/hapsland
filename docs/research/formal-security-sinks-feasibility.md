# Hapsland source access and sink feasibility

Updated 2026-09-24. Advisory source inspection for the direct-event v1 profile. This is neither an adopted security specification nor runtime proof. Scope starts with the [declared production profile](../direct-event-v1-supported-profile.md); legacy review, other host adapters, and other platforms need separate evidence. No live request, runtime probe, or implementation change was made for this note.

## Main finding and required ordering decision

The resident checks path eligibility during preparation, then stores prepared source in memory. Before evaluation, it reloads settings and rechecks consent, root identity, and credential authority, but passes `job.prepared` to `evaluatePrepared` without checking the newly loaded file policy against that path. The later publication step re-runs `prepareObservation` under current settings and may suppress findings, but provider egress has already occurred. Thus `prepare → add exclusion → dispatch` is the first conformance scenario to reproduce, not yet a demonstrated leak. [Preparation and policy gate](../../src/direct-event/pipeline.ts#L197), [queued evaluation](../../src/resident/server.ts#L1235), [post-evaluation revalidation](../../src/resident/server.ts#L1428).

An achievable first rule is: a restrictive configuration update or consent revocation **completed before the dispatch authorization read begins** prevents this unit's source submission. The gate rereads the file-backed authorities and checks the prepared path against those values before allowing provider use. A request already handed to the transport cannot be recalled. A change that races after the read may still allow the request; a stronger guarantee would require serialized configuration/consent mutation with dispatch, an epoch under shared ownership, or equivalent synchronization. Merely doing two independent reads near `model.decide` does not make file-backed authority atomic. The current code reloads configuration before credential resolution, then can wait at several asynchronous steps before `model.decide`; define the read boundary and test ordered traces separately from racing traces. [Evaluation sequence](../../src/resident/server.ts#L1241), [provider call](../../src/direct-event/pipeline.ts#L353).

## Exact observation seams for a connected gate

1. **Ingress:** invoke the actual adapter and resident admission for synthetic patches; capture the raw IPC frame before decode and assert that excluded-path added lines are removed at the chosen discard point. Merely asserting a skipped review would miss source already delivered to the resident. [Adapter](../../src/direct-event/adapter.ts#L28), [transport decode](../../src/resident/server.ts#L1591).
2. **File reads:** use `prepareObservation` with its existing `captureHooks.sourceRead` for a fast unit-level signal, but observe actual `open/read` system calls or an instrumented Node filesystem boundary in a packaged subprocess. The hook fires *after* bytes are read and cannot certify absence of all read paths; on macOS the child helper must also be observed. Compare source file identities, not just string path names. [Capture hooks](../../src/direct-event/capture.ts#L20), [Linux read](../../src/direct-event/capture.ts#L98), [macOS helper](../../src/direct-event/capture.ts#L35).
3. **Provider egress:** drive the real resident queue and real `evaluatePrepared`. A controlled `DecisionModel` can establish whether the production gate invoked the provider, but it is a lower boundary than the actual HTTP body. A separate offline transport capture must run the installed `@effect/ai-typesafe` serialization and record URL, method, header *names and credential placement*, and exact body without a live Jev request. The test must use a synthetic credential, compare its placement without retaining real secret values, and fail on an unexpected destination, body credential, or extra request. [Resident call site](../../src/resident/server.ts#L1319), [provider implementation](../../node_modules/@effect/ai-typesafe/src/TypeSafeClient.ts#L98).
4. **Local effects:** in an isolated subprocess with all state/runtime/demo paths directed into a temporary root, snapshot and inspect every created file and captured stdout/stderr. Also record attempted writes, because a blocked write may leave no file. Include the socket payload and controlled-mode outputs as distinct sinks. A process-level filesystem/network observer should supplement, rather than replace, schema checks of known stores.
5. **Artifact coverage:** run the same synthetic marker cases against the packaged CLI/resident and native helper for the declared platform. Source-level Effect tests and a model driver are useful for trace generation, but they cannot establish that packaged code has no alternate I/O path. The current installed-package conformance machinery is the natural outer harness. [Supported profile and package conformance](../direct-event-v1-supported-profile.md).

The gate must call production policy functions and production preparation/dispatch. Its expected decisions should come from the formal trace contract and independent sink observations, **not from a mocked copy of `eligibleNamedPath` or the same authorization helper under test**. A spy on `DecisionModel` alone proves only calls reaching that layer; it does not inspect the complete HTTP encoding or direct network calls. Conversely, a wire capture alone misses excluded source read into memory or written to disk.

## Candidate invariants and adversarial traces

| Invariant for the initial model/driver | Concrete trace or mutation that must fail |
| --- | --- |
| Excluded named path causes zero source-content reads after path selection. | Exclude before capture; alias path or symlink replacement; deliberately bypass `eligibleNamedPath` and observe `open/read`. |
| No provider dispatch contains a fragment from a path excluded by a configuration update completed before dispatch authority is read. | Prepare eligible file; complete config update to exclude it while queued; resume dispatch authorization; deliberately remove the reauthorization check. Repeat with multiple queued units and changed include list. Do not infer a guarantee for a mutation racing after the authority read. |
| A consent revocation completed before dispatch authority is read prevents subsequent dispatch. | Prepare; complete revocation before the authorization read; resume. Mutate out consent check. Record the exact point when an in-flight request is considered sent. A revocation racing after the read needs separate semantics. |
| A prepared unit remains bound to its physical root and source identity at dispatch. | Replace root/Git admin identity or mutate source after preparation; verify no stale send. Distinguish source mutation from path exclusion: current publication revalidation handles later delivery, not egress. |
| Persisted and emitted values match declared per-sink schemas; source markers cannot appear in unauthorized disk files, stderr/stdout or IPC response. | Inject marker-bearing exception; enable debug; inspect startup diagnostic; mutate an activity/owner/diagnostic write to include source. Also check ordinary mode with debug off. |
| Every provider-bound byte is accounted for by approved fields, fragments, metadata and rule text. | Add an unrelated declaration or source-bearing metadata field; mutate serializer or request construction and require the captured body check to fail. Detailed fragment contract belongs to the parallel payload investigation. |

For an initially bounded model, represent files by stable identities, policy revisions, consent state, prepared units, a queue, and send/write events. Expose `prepare`, `changePolicy`, `revokeConsent`, `dispatch`, `fail` and `collect`. Assert safety on observed effects, not solely on abstract state. Cover both `reviewObservation` and resident dispatch if both remain supported entry points: the immediate path also authorizes consent and root before `evaluatePrepared` but does not reload changed policy after preparation. [Immediate review](../../src/direct-event/pipeline.ts#L422).

## Feasibility limits and next concrete step

The smallest useful reproduction is an offline resident run with a deterministic gate between prepare and evaluate, a synthetic file carrying a unique marker, a newly written exclusion, and an observer at `DecisionModel.decide`. The existing `afterPrepare` and `beforeEvaluate` hooks support scheduling this race in-process; `REVIEW_RESIDENT_BACKEND_GATE_PATH` supports a packaged subprocess gate, though its placement must be checked against the desired ordering. [Resident hooks](../../src/resident/server.ts#L358), [backend gate](../../src/resident/server.ts#L1416). This would turn the current source-inspected gap into runtime evidence. A subsequent production change can add a dispatch authorization seam and a second gate at the encoded HTTP request.

Claims should remain bounded: a passing finite trace suite shows exercised conformance, not universal TypeScript information-flow security. The filesystem and socket observers need documented platform coverage and trusted assumptions; Jev's server-side retention and agent-host ingestion are outside this Hapsland process boundary. The source was inspected at the current checkout; line references and behavior should be rechecked after concurrent edits.
