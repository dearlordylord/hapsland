# Is the TypeScript sidecar reducer ready to sunset?

Research date: 2026-09-27. Scope: repository source at `feat/bend-full-flow`; this is an architecture assessment, not a code removal.

## Answer

**Its business rules for the shared, simplified flow have a Bend counterpart, but the TypeScript reducer is not merely historical yet.** The current visualization uses it as its *interactive engine*, and the Bend flow is replayed from the history that engine accepts. The TypeScript reducer is also the independent comparison oracle in the Bend package's differential check. Neither reducer is the resident's production backbone: production calls generated functions from richer Bend policy and ledger modules, while TypeScript runs effects and state orchestration. This assessment concerns retiring TypeScript `flow.ts`, not deleting `Flow.bend`; other Bend modules still import `Flow.bend` types. [Main UI](../packages/agent-flow-viz/src/main.ts#L77-L157), [Bend replay](../packages/agent-flow-viz/src/bend-comparison.ts#L134-L177), [parity runner](../packages/agent-flow-bend/scripts/check-sidecar-parity.mjs#L81-L105), [production imports](../src/resident/composed-delivery.ts#L1-L28), [production ledger](../src/resident/capacity.ts#L1-L10), [Bend scope](../packages/agent-flow-bend/README.md#L20-L34), [Bend import](../packages/agent-flow-bend/Work.bend#L1-L3).

| Role of the TypeScript reducer | Superseded today? |
| --- | --- |
| Production decision authority | Yes; production calls richer generated Bend policies. |
| Rules of the simplified one-agent flow | A Bend counterpart exists and matches the tested traces. |
| Interactive page engine and scenario projection | No; current controls and timelines still call it. |
| Independent Bend regression oracle and dynamic state assertions | No replacement is present in the checked paths. |

**Recommendation:** begin a *planned* sunset, but do not delete `flow.ts` now. First make the compiled Bend flow the UI's input and history authority, then decide deliberately how to retain independent behavioral regression evidence. A Bend-only diagram would remove the visual difference report by construction. A production-flow visualization is a separate design problem because `Flow.bend` omits much of the resident lifecycle. This recommendation follows from the dependencies and model scope below; it is not a claim of an unobserved runtime defect. [UI state ownership](../packages/agent-flow-viz/src/main.ts#L60-L65), [comparison](../packages/agent-flow-viz/src/main.ts#L351-L407), [scope map](../packages/agent-flow-viz/src/main.ts#L411-L435).

**Comparison limit:** the interactive page records only actions accepted by the TypeScript reducer, then feeds that accepted history to Bend. A manual action rejected by TypeScript is not recorded, so the page cannot show a case where Bend would accept that action. The separate `compareHistory` function can test rejected inputs, and the build check does so on a focused rejection sequence. This is an inference from the control flow, not an observed divergence. [TypeScript admission and recording](../packages/agent-flow-viz/src/main.ts#L77-L140), [Bend history input](../packages/agent-flow-viz/src/main.ts#L351-L368), [rejection check](../packages/agent-flow-viz/scripts/check-projection.mjs#L17-L35).

## What is already superseded, and what is not

**Fact — overlapping rules:** `Flow.bend` implements the same abstract one-advicee state and emits the same ordered flow changes as the sidecar. The package check asserts state, decision, rejection, and change parity on 113 traces, including generated accepted and rejected events. This is substantial evidence that no distinct *intended* rule is currently required from TypeScript for that subset, but the finite trace check is not an exhaustive equivalence proof. [Bend module description](../packages/agent-flow-bend/README.md#L3-L9), [parity assertions](../packages/agent-flow-bend/scripts/check-sidecar-parity.mjs#L81-L105), [trace count and construction](../packages/agent-flow-bend/scripts/check-sidecar-parity.mjs#L107-L152).

**Fact — production:** the resident imports generated Bend policy functions and a generated ledger, not the sidecar reducer or `flow.generated.js`. The `Flow.bend` generated entry points are built for visualization and parity checks; production uses separate admission, work, round, lifecycle, delivery and other gates. `Lifecycle.apply` is also a tested aggregate model rather than the production's single state machine. [Resident imports](../src/resident/server.ts#L61-L81), [composed delivery imports](../src/resident/composed-delivery.ts#L1-L28), [ledger imports](../src/resident/capacity.ts#L1-L10), [Bend README](../packages/agent-flow-bend/README.md#L20-L34).

**Fact — missing production scope:** the sidecar models one review item per edit and a simplified virtual round. The current page itself lists permits, fan-out, final Stop cutoff, finding collection, leases, ticket outcomes, logical capacity, revisions, reuse, cache, notices, and retention as outside the sidecar comparison. Native identities, clocks, source capture, Jev calls, IPC and output remain TypeScript concerns. Therefore replacing the sidecar diagram with a Bend `Flow.bend` diagram would still **not** make it a complete production-flow visualization. [Sidecar boundary](../packages/agent-flow-viz/src/flow.ts#L62-L65), [scope list](../packages/agent-flow-viz/src/main.ts#L411-L435), [Bend extension plan](../packages/agent-flow-bend/EXTENSION-PLAN.md#L69-L86).

**Inference — remaining value:** the TypeScript reducer now has mainly an independent *comparison* value and a current *implementation* role in the page, rather than unique production authority. Its structural assertions check packet uniqueness, lease consistency, closed-round emptiness, and item conservation after accepted steps. The focused `Flow` laws I found cover selected examples, not an obvious general invariant corresponding to all four checks. Dropping `flow.ts` would remove these runtime checks from the visualization unless equivalents are added. This is a gap in observed assurance, not proof that Bend violates an invariant. [Sidecar assertions](../packages/agent-flow-viz/src/flow.ts#L209-L236), [focused Bend laws](../packages/agent-flow-bend/LAWS.bend#L769-L809).

## Safe sunset sequence

1. Move view-facing event/state/change types, labels and scenario fixtures into a neutral visualization contract. Keep native timing evidence separate. [Reducer contracts](../packages/agent-flow-viz/src/flow.ts#L51-L60), [timeline evidence](../packages/agent-flow-viz/src/timeline.ts#L14-L39).
2. Make the UI accept, reject and replay events through generated Bend `bendInitial`, `bendStep` and `bendChanges`. Build route discovery, manual event availability and history navigation from that result. The current Bend adapter already demonstrates encoding and projection but is a passive replay, so this is implementation work, not a switch in configuration. [Bend wrapper](../packages/agent-flow-bend/scripts/build-flow.mjs#L27-L38), [adapter](../packages/agent-flow-viz/src/bend-comparison.ts#L84-L113), [UI actions](../packages/agent-flow-viz/src/main.ts#L77-L178).
3. Before removing the TypeScript oracle, freeze meaningful scenario expectations for accepted/rejected steps, ordered changes, conservation and finish choices, or replace them with an independent production-vs-model event ledger. Keep Bend laws and source-backed projection checks. This is a recommendation for independent regression detection, not evidence that existing parity fails. [Current oracle](../packages/agent-flow-bend/scripts/check-sidecar-parity.mjs#L81-L105), [scenario source](../packages/agent-flow-viz/src/scenarios.ts#L3-L20), [Bend tests](../packages/agent-flow-bend/package.json#L6-L9).
4. Then remove `flow.ts` and the side-by-side comparator, update the visualization copy to say precisely that it shows `Flow.bend`'s limited abstract flow, and leave the broader production Bend policy map visible. If the user needs a true production diagram, build it from resident event/decision traces rather than asserting that the abstract reducer is the production call graph. [Current caveat](../packages/agent-flow-viz/src/main.ts#L373-L382), [production scope map](../packages/agent-flow-viz/src/main.ts#L411-L435).

## Open questions

- Is the desired long-term page a teaching simulator of the abstract flow, or a trace viewer of actual resident decisions? They have different event sources. Current UI is explicitly an example with no live runtime connection. [UI reset](../packages/agent-flow-viz/src/main.ts#L60-L64), [page caveat](../packages/agent-flow-viz/src/main.ts#L373-L382).
- Should the independent TypeScript oracle be archived as fixed baseline history, retained until a resident event ledger exists, or replaced by contract-derived expected traces? Removing it now removes a comparison that can expose later Bend regressions on overlapping behavior. [Parity script](../packages/agent-flow-bend/scripts/check-sidecar-parity.mjs#L81-L105), [comparison status](../packages/agent-flow-viz/src/main.ts#L403-L408).
