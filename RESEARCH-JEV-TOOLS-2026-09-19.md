# Jev / TypeSafe System One tools for coding agents and code review

> **Comparative status:** Superseded by [`PRODUCT-RESEARCH-ADVISORY-2026-09-19-PASS-2.md`](./PRODUCT-RESEARCH-ADVISORY-2026-09-19-PASS-2.md) for architecture decisions. Retained as a bounded inventory of Jev-specific community projects; product terminology is defined in [`CONTEXT.md`](./CONTEXT.md).

**Checked:** 2026-09-19 (America/Montreal)  
**Scope:** Primary-source check of TypeSafe documentation, the TypeSafe GitHub organization, GitHub repositories and manifests, npm registry records, and public marketplace/registry search surfaces. No live TypeSafe calls or end-to-end installs were performed.

## Bottom line

There is a real Jev developer-tool ecosystem, but it is extremely young and should not be mistaken for a mature official product line.

- **Jev itself is a hosted decision model, not a coding agent, linter, MCP server, or code reviewer.** TypeSafe describes it as its flagship and first “System One” model: callers send state plus typed questions, and receive constrained answers and probability distributions. The official endpoint is `POST https://api.typesafe.ai/v1/systemone`; the current stable alias is `jev-latest`, pointing to `jev-1.13.0` when checked. [TypeSafe introduction](https://docs.typesafe.ai/introduction), [API reference](https://docs.typesafe.ai/api), [models](https://docs.typesafe.ai/models).
- **The one official agent-facing package found is TypeSafe's agent skill.** It teaches a coding agent how to design and implement Jev calls. It is installable as a Claude Code plugin from TypeSafe's repository-based marketplace, or through `npx skills add` for Codex and other compatible agents. It does not itself intercept edits, review diffs, expose MCP tools, or enforce policy. [Official agent-skill documentation](https://docs.typesafe.ai/agent-skill), [official `typesafe-ai/skills` repository](https://github.com/typesafe-ai/skills), [marketplace manifest](https://github.com/typesafe-ai/skills/blob/main/.claude-plugin/marketplace.json).
- **Actual MCP, hook, lint, and review implementations exist, but the examples verified below are community projects.** Several have npm packages or runnable manifests; others are repository-only. Most relevant repositories were created between 2026-09-16 and 2026-09-18, so stars, versions, APIs, and maintenance signals are not yet durable.
- **No official TypeSafe MCP server, code-review action, Codex lifecycle plugin, or semantic linter was found** in TypeSafe's public GitHub organization or documentation index as of the check date. This is a bounded negative finding, not proof that no private, unindexed, or newly published integration exists. [TypeSafe GitHub organization](https://github.com/typesafe-ai), [documentation index](https://docs.typesafe.ai/llms.txt).

## Marketplace and registry findings

- **Claude Code:** verified repository-hosted marketplace manifests exist for the official TypeSafe skill and community hooks such as limpet. These require adding the repository as a marketplace. This is different from a centralized endorsement or review.
- **Codex:** community repositories contain `.codex-plugin/plugin.json` manifests (for example Jev Review, jev-guard, save-token-jev, and limpet), and some repositories expose their own marketplace catalogs. A manifest or self-hosted catalog means the repository can be packaged for Codex; it does not establish that OpenAI distributes, endorses, or audits it.
- **npm:** exact registry records were verified for `@typesafe-ai/sdk`, `@ai-sdk/typesafe-ai`, `@jkudish/jev-mcp`, `jev-mcp`, `jev-eval-mcp`, `@y0usaf/pi-jev`, `jev-guard`, `@jevlint/cli`, `@lakeday/perch`, `jev-pref`, and the review packages named above. NiazMorshed2007's Jev Review explicitly has no npm publication.
- **GitHub Marketplace / VS Code Marketplace:** no attributable Jev/TypeSafe coding-agent or review listing was verified in the public searches performed. The GitHub Action above is usable directly from a repository tag without a Marketplace listing.
- **MCP Registry:** several working repository/npm MCP servers were found, but no official TypeSafe-owned MCP server or registry listing was verified. This pass therefore links to source and package records rather than claiming registry publication.

## Negative findings and cautions

1. **No official Jev code reviewer was found.** The TypeSafe docs explain how to build with Jev and ship an agent skill, SDKs, and API. The TypeSafe GitHub organization did not expose a review bot, GitHub Action, MCP server, Codex plugin, or linter in its public repository list when checked.
2. **A plugin manifest is not adoption evidence.** Several repositories check in Claude or Codex manifests and self-hosted marketplace catalogs. That establishes installability from source, not centralized publication, security review, active maintenance, or broad use.
3. **Most community entries are only days old.** Representative review/hook repositories in this report were created during 2026-09-16 through 2026-09-18. Versions and star counts can change hourly, and one Codex-specific project was already archived.
4. **Model judgment is not deterministic static analysis.** Jev returns schema-conforming probabilities, but the official docs do not claim every answer is correct. Any blocker should be calibrated on project data, expose uncertainty, and retain deterministic tests/static analysis for rules those tools can express.
5. **Remote review sends evidence off-machine.** Unless a project uses a local substitute, it sends some combination of diffs, code, messages, or tool arguments to TypeSafe or another configured gateway. Each integration's truncation, exclusions, retries, and fail-open/fail-closed behavior must be reviewed independently.
6. **No runtime validation was performed here.** Package existence, manifests, source layout, README behavior, and registry metadata were checked. API credentials were not used, packages were not installed, and vendor/project latency, cost, accuracy, and security claims were not reproduced.

## Name collisions and inclusion test

“Jev,” “TypeSafe,” and “System One” are not unique search terms. A result was treated as part of this ecosystem only when its primary source tied itself to TypeSafe AI through one or more of:

- `https://api.typesafe.ai/v1/systemone` or `docs.typesafe.ai`;
- the `jev-latest` / `jev-1.13.0` model identifiers;
- `TYPESAFE_API_KEY`;
- the official `typesafe-ai` GitHub organization or SDK package names.

Concrete collisions found:

- The exact npm name [`jev`](https://www.npmjs.com/package/jev) is version `0.0.0`, was created in 2021 and last modified in 2022, and had no TypeSafe model description or repository metadata. It predates this Jev product and should not be installed as its SDK.
- The exact npm name [`typesafe`](https://www.npmjs.com/package/typesafe) dates to 2015 and is not the TypeSafe AI SDK. Many `typesafe-*` packages concern ordinary TypeScript type safety. The official JavaScript SDK is the scoped `@typesafe-ai/sdk` package.
- GitHub name searches also return unrelated older projects such as [jEveAssets](https://github.com/GoldenGnu/jeveassets), [JeVois](https://github.com/jevois/jevois), and [Jevix](https://github.com/ur001/Jevix). Their names alone are not evidence of a TypeSafe integration.
- “Open Jev,” “Jev-compatible,” and System One replicas were excluded from the tool table unless they integrated the TypeSafe service. Such projects may reproduce the wire contract or decision pattern without shipping TypeSafe's weights or calling its API.

## Search limitations

- Searches were performed on 2026-09-19 against public, unauthenticated surfaces. Private repositories, private marketplaces, Discord-only releases, and unindexed/new pages are outside scope.
- GitHub and web search are ranking/indexing systems, not complete inventories. GitHub API repository metadata and raw manifests were used to verify selected candidates, but no authenticated global GitHub code-search crawl was performed.
- npm was checked by exact package names and a keyword query. Other registries (PyPI, crates.io, Hex, JSR, Go modules) were not exhaustively enumerated because this report prioritizes coding-agent and review surfaces.
- Marketplace search pages and MCP registries can be client-rendered, rate-limited, or inconsistently indexed. Negative marketplace/registry findings above mean “not verified in this pass,” not “does not exist anywhere.”
- Community README claims are cited as claims by their maintainers. Only TypeSafe's own docs and repositories are treated as authoritative for Jev's product/API behavior.

## Practical conclusion

For a coding-agent integration today, the most defensible stack is:

1. use the official TypeSafe API/SDK and official agent skill for the model contract;
2. treat community MCP servers, hooks, linters, and actions as reference implementations requiring source review and pinned versions;
3. keep enforcement policy in ordinary code, measure thresholds on labeled repository examples, and preserve a human or deterministic fallback for high-impact decisions;
4. document exactly which source/diff material leaves the machine.

The ecosystem demonstrates that Jev can be wired into MCP, agent lifecycle hooks, pre-commit, CI, and PR review. It does **not** yet demonstrate a single official, mature, broadly adopted Jev code-review plugin.
