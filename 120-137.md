## What the branch currently decides

- **One decision engine:** Production and the dashboard use [`Canonical.step`](packages/agent-flow-bend/Canonical.bend). TypeScript measures time, reads files and Git state, talks to Jev and hosts, and passes those facts to Bend. Display and counters may stay in TypeScript only while they cannot change a product decision. Native facts such as `currentWork`, `selected`, `credentialReady`, and `extraPending` need review whenever their definitions change.
- **Capacity:** The resident reserves logical review space, with limits of **512 items/64 MiB shared** and **16 items/2 MiB per partition**. Each child has a separate partition; Claude also separates tool calls, and composed rounds separate generations. [#146](https://github.com/dearlordylord/hapsland/issues/146) will investigate which size and count limits should be configurable. A refused unit does not stop a later, smaller unit from fitting. Refusal is immediate; [#139](https://github.com/dearlordylord/hapsland/issues/139) will design bounded backpressure with configurable expiry. Today's capture limit is **32 KiB per file**. The larger cross-file target belongs to [#138](https://github.com/dearlordylord/hapsland/issues/138).
- **Work and Stop:** Resident jobs dispatch FIFO with **eight concurrent slots**, shared by source preparation and review-unit evaluation. Each unit evaluation makes one Jev decision call. Stop uses the original deadline, waits for known unfinished work, and currently allows at most **four continuations**. A temporary revalidation failure can leave advice eligible until another collection opportunity or expiry.
- **Which work stays current:** A changed input supersedes older work only for the same subject. Exact input and credential identity control reuse; only successful Jev evaluations enter the bounded LRU cache. Future cross-file evidence must become part of those identities before reuse is safe.
- **Configuration and rules:** A configured runtime with a usable Jev credential needs no separate repository grant. File exclusions accumulate across user and project settings; protected and ignored paths remain excluded. Bend decides file admission, rule applicability, strict probability thresholds, finding rank, and count. The current rule schema covers same-file inputs; [#138](https://github.com/dearlordylord/hapsland/issues/138) must define the broader evidence contract.
- **Delivery:** A successful hook stdout write counts as delivery, without a runtime or model receipt. Stop does not repeat a submitted background finding; an uncertain background write remains eligible for one Stop offer. Failed or uncertain writes do not count as clear. Agent output contains actionable findings only. Operational failures stay in source-free resident diagnostics.
- **Claude's current hook flow (#145):** Background and Stop use the same collection rules as the immediate edit response. Blocking the current edit requires a current user opt-in and remains subject to project policy. The self-imposed **10 KiB** encoded output limit includes Claude wrapper text; there is no separate finding-count cap. Internally, observation and collection ownership have separate source-free IDs.
- **Cleanup:** Idle cleanup releases logical state only when native and Bend ownership checks pass. It does not govern resident process lifetime; that is [#143](https://github.com/dearlordylord/hapsland/issues/143). Existing grant files are left untouched even though current admission ignores them.
