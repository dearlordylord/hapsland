## What the branch currently decides

- **One decision engine:** Production and the dashboard use [`Canonical.step`](packages/agent-flow-bend/Canonical.bend). TypeScript measures time, reads files and Git state, talks to Jev and hosts, and passes those facts to Bend. Display and counters may stay in TypeScript only while they cannot change a product decision. Native facts such as `currentWork`, `selected`, `credentialReady`, and `extraPending` need review whenever their definitions change.
- **Capacity:** The resident reserves logical review space, with limits of **64 items/8 MiB total** and **16 items/2 MiB per advicee**. A refused unit does not stop a later, smaller unit from fitting. Refusal is immediate; retry and backpressure belong to [#139](https://github.com/dearlordylord/hapsland/issues/139). Today's capture limit is **32 KiB per file**. The larger cross-file target belongs to [#138](https://github.com/dearlordylord/hapsland/issues/138).
- **Work and Stop:** Reviews dispatch FIFO with **two concurrent slots**. Stop uses the original deadline, waits for known unfinished work, and allows at most **four continuations**. A submitted background finding can be offered at Stop once more after fresh validation. A temporary revalidation failure can leave advice eligible until another collection opportunity or expiry.
- **Which work stays current:** A changed input supersedes older work only for the same subject. Exact input and credential identity control reuse; only successful Jev evaluations enter the bounded LRU cache. Future cross-file evidence must become part of those identities before reuse is safe.
- **Configuration and rules:** A configured runtime with a usable Jev credential needs no separate repository grant. File exclusions accumulate across user and project settings; protected and ignored paths remain excluded. Bend decides file admission, rule applicability, strict probability thresholds, finding rank, and count. The current rule schema covers same-file inputs; [#138](https://github.com/dearlordylord/hapsland/issues/138) must define the broader evidence contract.
- **Delivery:** A host write establishes submission, not agent visibility or repair. Failed or uncertain writes do not count as clear. Findings and failed review units can coexist, and diagnostics retain both. Codex stops at the first operational notice that cannot fit; Claude can skip it and try a later one.
- **Claude's current hook flow (#145):** Background and Stop use the same collection rules as the immediate edit response. Blocking the current edit requires a current user opt-in and remains subject to project policy. The **five-finding/2 KiB** limit includes wrapper text and notices in the final Claude response. Internally, observation and collection ownership have separate source-free IDs.
- **Cleanup:** Idle cleanup releases logical state only when native and Bend ownership checks pass. It does not govern resident process lifetime; that is [#143](https://github.com/dearlordylord/hapsland/issues/143). Existing grant files are left untouched even though current admission ignores them.
