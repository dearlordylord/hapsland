# Proposed amendment after the Stage 2 token stop

**Status:** proposal for owner review; not in force. No further host session or Jev call has begun. The [original registration](../../../docs/issue-95-stage2.md) and [Arm A result](./arm-a-pilot-report.md) remain intact.

## Trigger and accounting clarification

Pair 1 Arm A reported 1,336,616 input tokens, including 1,253,632 cached input tokens, and 36,983 output tokens. Total reported input plus output was 1,373,599, above the original 250,000-token per-run stop. Uncached input plus output was 119,967, below that threshold, but the original protocol did not specify excluding cached input. Stopping before Arm B preserves that conservative reading. The host did not report a dollar charge, so financial cost cannot be inferred from the token record alone.

For any new run, define the metered token categories explicitly: `input` includes cached input; `uncached input = input − cached input`; `output` includes reasoning output. Avoid adding cached or reasoning subsets twice. Continue reporting all five raw categories. A proposed new guard is **250,000 uncached input plus output tokens per run**, **750,000 across the four paired runs**, and a separate **2,000,000 cached input tokens per run**, **8,000,000 across the four runs**. These are post-run stop-before-next-session limits because Codex exposes the counters at turn completion. The 20-minute per-session timeout, four planned sessions, at most two infrastructure-only retries, 120-minute hard host-start ceiling, and the 80 Jev requests/2 MiB source per A run remain. Stop before another session at US$25 aggregate Jev or US$40 aggregate Codex charge if actual billing becomes observable; when unavailable, record cost as unavailable and enforce token, time, request, and source ceilings. Do not estimate dollars from a guessed rate.

The source-free delivery instrumentation should be tightened before any new run: record supported/unsupported analyzer status at each edited type-file hook, with only path, root name, reason, byte count, and source hash; record each submitted rule ID and its time; and classify later model messages for exact rule-ID acknowledgement without retaining their text. An edit after feedback with a changed source hash is an attempted repair, not proof that the model saw advice. The temporary host stream may be inspected for a specific acknowledgement during the session, but must be discarded after a sanitized classification. The final tree and offline checks remain the only retained source artifact. This improves the exposure and visibility denominator without changing the production review advice.

## Choice A: fresh matched pilot (recommended)

Treat the completed Arm A as an excluded feasibility pilot. After accepting this amendment and checking the revised meter offline, start two **new** pairs in A–B then B–A order with the same frozen task, Luna/max host settings, platform, and tools. Count only those four new artifacts for pair differences and variance. Record the old Arm A separately with no comparative score. This avoids using an outcome observed before the revised stopping rule to choose the first paired sample. Maximum incremental exposure is four host sessions plus at most two infrastructure-only retries, 120 host minutes, and 160 Jev requests across the two A sessions. The actual dollar cost remains unknown unless billing evidence becomes available.

## Choice B: transparent exploratory continuation

Retain the completed Arm A as pair 1 Arm A and run B1, B2, and A2 under the new limits. Report the original token-stop violation and the post hoc amendment alongside every comparison. This saves one A session and up to 80 Jev requests, but the resulting pairs are **exploratory** because one treatment outcome was observed before changing the stop rule and instrumenting exposure. The new per-edit exposure ledger would not exist for Arm A; its individual finding visibility remains unproven. Do not present a mean pair difference from this path as confirmatory evidence.

Either choice needs explicit owner acceptance before resuming. If the owner rejects both, close Stage 2 as incomplete with the existing single-arm feasibility result and no quality-effect claim.
