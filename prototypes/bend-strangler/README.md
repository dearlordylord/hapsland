# Bend migration implementation prototype

**Purpose:** Preserve the accumulated authored TypeScript-to-Bend migration implementation, proofs and experiment runners as reviewable source captures.
**Audience:** Contributors implementing and reviewing the migration, including coding agents.
**Status:** Temporary implementation prototype; incomplete and not connected to production Canonical preparation.
**Authority:** Implementation artifacts only. [Migration guidance](../../docs/bend-migration.md) and the accepted [Canonical flow architecture](../../docs/architecture.md#canonical-ownership-of-the-product-flow) own requirements.
**Expected use:** Continue the complete resolver and language-session migration, prove its original guarantees, and qualify the composed production consumer before adoption. Some declarations remain unproved; individual proof passes do not qualify the subsystem.
**Lifecycle:** At acceptance of the Canonical-connected preparation/resolver subsystem, consolidate accepted implementation and laws into their production package owners, transfer current acceptance evidence to its designated owner, update inbound links, and delete this prototype tree. Raw experiment outputs remain ignored under `evidence/bend-strangler`.

Bend source captures use `.bend.txt` because the pinned formatter cannot parse some checked proof constructs. Their exact bytes and original paths are recorded in `source-inventory.json`. Run `node prototypes/bend-strangler/restore-sources.mjs` to reconstruct missing sources under ignored `evidence/bend-strangler`; the restorer verifies every hash and refuses to overwrite differing current work. An optional destination argument restores into a separate directory. Run proof and experiment entry points from that restored tree so their original relative imports resolve. Promote accepted source to ordinary formatted production files at subsystem acceptance.

The common resolver candidate still lacks current Go/session semantics and persistent Python child integration. Its original whole-entry physical corpus no longer passes differential qualification. Canonical launch/cancel/result acceptance, universal correspondence and lifetime proofs, TypeScript removal and performance acceptance remain open.

The Python child now owns signed authority accounting, capture/membership/stat/revalidation, absolute-root policy/discovery, module/package alternatives, lexical/module scope, import namespace/static authority, package parents, complete moduleTarget and complete resolveImport. ModuleTarget agrees with native results and ordered effects on 21 physical cases; resolveImport agrees on 26 cases including cycles, depth, forwarding, shadowing, authority transfer and bounded admission. These consumers use cached roots and injected capture, so they do not establish production session equivalence.

A separate persistent-session consumer compares the actual current native GraphSession against Bend preparation, inspect admission, resolveImport, usage and revalidation. Nine physical cases passed with actual eligibleNamedPath, captureStable, root identity and caller cache; they include repeated resolution, transfer accounting, membership changes, unstable reads and terminal deadline/work refusals. The composed pure kernel checks. These are finite checks, not universal equivalence proofs or common resolver/Canonical acceptance. InspectSource still calls Hapsland-owned TS extraction as an explicit intermediate boundary; adoption must decide its proper owner scope or migrate its policy, rather than label it a native foreign engine.

Review exposed a namespace mutation sibling-tail bug, now fixed, and a native lambda-body wrapper-identity instability, independently reproduced over 300 trees. Both native exclusions now use the existing sameSyntaxNode primitive. The corrected authority consumer passes 67 sources and 144 regex boundaries; 43 production Python pipeline/cross-file tests and check:fast passed. Complete session/effect correspondence, lawful syntax/fuel bounds and resolver/Canonical lifetime proofs remain open.

The latest measured existing-production build ratio is 1.0461, exceeding the unchanged parity threshold of 1; execution ratio is 0.6983 and passes. Raw series and stage attribution remain ignored evidence. They measure existing production after master integration and the explicit native oracle correction, not the unadopted resolver candidate. Acceptance still requires connected Bend, deleted superseded TypeScript and the fully composed production consumer.
