ASTRA MEDIUM DESIGN REVIEW — RESTORED SPATIAL GAME
Validation date: 2026-10-01
Purpose: assess architecture teaching and the restored native tower-game interaction.
Status: completed bounded design review. Root owns final native verification and all further architecture/mechanics assessment.
Authority: design judgement and implementation evidence, not accepted product contract, formal proof, or measured human learning.
Expected use: review this throwaway prototype and decide which mechanics/layout to develop next.
Lifecycle: consolidate useful decisions into the next accepted prototype/design owner and delete this snapshot when the canonical-defense experiment is replaced or removed.

Scope and authority
The prototype imports the actual packages/agent-flow-bend/Canonical.bend. It does not import RoadGame or reproduce Canonical transitions. The current product baseline is master 9f38e7e, merged into this branch. The dashboard and production adapter use the generated form of this same Canonical module. Game geometry, service delays, risk, gold and health belong to the synthetic host. They are not production behavior guarantees. No product-core modifications were made for this experiment.

The restored interaction is materially different from the superseded global-dock design: seven manually positioned tower families, range circles, exact next-effect previews, automatic shots, selection and three-level upgrades. Roads are orthogonal. Buildings are64 × 48, with visibly smaller internal actors and finite serpentine routes. Layout switching is locked once towers or a wave exist, preventing free relocation/coverage changes.

Source findings and resolutions
- Rapid, Relay and Coordinator act only on eligible active work with positive remaining work. Refiner changes only synthetic unresolved risk; it does not shorten service work or erase observed PendingFinding. Initial risk is 100%; stored draws are fixed, not rerolled each tick. Parent quality is inherited by future children.
- Radius coverage and hover values use the same host effect helpers. Selected inspection now uses the actual tower, fixing the former level-one-radius false-zero after upgrades.
- Parallelizer changes local HOST launch limits, capped by unchanged actual Canonical limits of 8. Packager changes host target 4..8 and serialization work 8→4/3/2 ticks/item; it does not reduce charged ledger bytes or increase the actual four-reservation budget.
- Output selection and duration freeze at reservation. Real CollectionFitCheck, reservation, leases and atomic Finish authorization/acknowledgement govern output. After the master merge, obsolete per-advice Stop authorization/terminal replay was removed: accepted FinishRecorded{Acknowledged} alone gates retirement of the exact committed selection, followed by FinishEnd. Refusal preserves retained work.
- Shield mitigates local game damage work, has finite 240 useful hot-tick charges and a shared half-per-building cap. Ledger occupancy remains unchanged. Existing shields take priority, so a new zero-marginal overlap stays idle.
- Finite phase progress derives from host work already completed, including shot boosts. Road travel uses authored distance, not a fast arbitrary cosmetic loop. Actors park when waiting; actual Canonical state remains the authority for phase and ownership.

Design recommendation
Use Switchback District as the baseline gameplay map: one legible itinerary leaves space for placement and makes range choices easy to compare. Use Forked Campus to teach one edit creating sibling units and both branches sharing Jev capacity; its populated CLEAR 1 frame provides the strongest architecture explanation. Resource Junction offers a different placement geometry and intake/output corridor arrangement, but shares the same underlying processing chain; it is not a different Canonical architecture. Map geometry intentionally changes host travel time and spatial coverage, so these are alternative boards rather than identical-timing experiments.

Limits and next evaluation
This remains a finite eight-source fixture with exactly two children per source, synthetic 10/20 logical byte payloads, deterministic simulated backend outcomes and host-authored delays. It does not establish variable-n fan-out behavior, production serialization size, live Jev behavior, balance, replayability or user learning. Health bars mirror shared game health, as the footer states; they are not independent building durability. Small IDs/stat text require careful reading at 1024×768, and the active-work panel shows only four units. Dense parked ownership must be read with the explicit counts rather than inferred from sprites alone. Linux ARM64 native execution is evidenced; macOS execution is not. No human engagement or comprehension study was run.
